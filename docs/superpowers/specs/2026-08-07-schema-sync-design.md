# 分库表结构预览与同步工具（schema-sync）设计

日期：2026-08-07  
状态：已作废（被 `2026-08-08-schema-sync-desktop-design.md` 替代）

## 背景与目标

业务按多租户、按年分库，分布在多个 MySQL 实例上。库名形如 `order_{年}_{租户}`，也有不分年的 `product_{租户}`。同一逻辑下的指定表结构必须一致，手工维护成本高且易漏。

本工具提供本地 Web 界面：**以某库中的表为模板**，扫描同源目标库同名表差异，**预览 SQL 并勾选后执行同步**。

## 范围

### 首版包含

- MySQL / MariaDB
- 多实例连接
- 按库名 glob 发现目标库
- 仅同步表组内指定表（非整库）
- 以模板表为真理来源
- 差异预览 + 逐项勾选执行
- 配置文件与页面双向编辑，落盘 YAML
- 连接密码密文存储

### 首版不包含

- PostgreSQL / SQL Server 等其它引擎
- 外键、分区定义的自动同步
- 数据迁移（只做结构）
- 云端多用户账号体系
- CI 命令行（可后续加）

## 架构

本地单进程：

```text
浏览器 UI
  → FastAPI 后端
      ├─ 配置读写（YAML）
      ├─ 密钥加解密（连接密码）
      ├─ 多实例连接
      ├─ 库发现 / Schema 抽取 / Diff / SQL 生成
      └─ 勾选执行 + 历史日志
  → 多个 MySQL 实例
```

- 默认监听 `127.0.0.1`
- 技术选型：Python FastAPI + Vite 轻量前端

## 配置模型

文件：`config.yaml`（路径可配置，默认项目/工作目录下）。

### 实例 `instances`

| 字段 | 说明 |
|------|------|
| `id` | 短名 |
| `host` / `port` / `user` | 连接信息 |
| `password` | 密文，形如 `enc:v1:<ciphertext>` |
| `enabled` | 可选，默认 true |
| `remark` | 可选备注 |

### 逻辑表组 `table_groups`

| 字段 | 说明 | 示例 |
|------|------|------|
| `id` | 组标识 | `order` |
| `database_pattern` | 库名 glob | `order_*_*` / `product_*` |
| `tables` | 要对齐的表名列表 | `[order, order_item]` |
| `instance_ids` | 扫描哪些实例 | `[main, shard-a]` |

页面修改与文件修改等价，保存时写回同一 YAML。

### 密码密文

- 本地主密钥文件：`.schema-sync.key`（权限建议 `600`）
- 对称加密采用 Fernet（`cryptography`）；YAML 中密码仅为密文
- API 永不返回明文密码；编辑连接时未改密码则保留原密文
- 页面录入或「导入后加密落盘」；不要求用户手写密文
- `config.yaml` 与 `.schema-sync.key` 均应被 gitignore；换机需同时拷贝密钥

## 同步工作流

1. 配置实例与表组并保存
2. 在同步工作台选择表组、模板实例与模板库
3. 扫描：在表组关联实例上，按 `database_pattern` 发现库，排除模板库本身；对 `tables` 中每张表对比结构
4. 展示差异项（按目标库分组），支持全选安全项 / 按库全选 / 单条勾选
5. 预览将执行的 SQL 汇总 → 二次确认 → 执行
6. 展示每条成功/失败；写入轻量执行历史

### 执行顺序与并发

- 按目标库串行，避免打爆实例
- 同一库内顺序：建表 → 加列 → 改列 → 索引变更
- 单条失败：记录错误；默认继续后续项，确认时可选「遇错即停」

## 对比与 SQL 生成

模板表结构为唯一真理（`SHOW CREATE TABLE` / `information_schema`）。

### 对比范围

- 列：存在性、类型、NULL、默认值、注释
- 主键、索引/唯一键（含列顺序）
- 表注释（默认开启）

### 不做（首版）

- 外键
- 分区
- 存储引擎 / 字符集的破坏性整表变更（明显不一致时仅提示）

### 差异项类型

| 类型 | SQL 意图 | 默认勾选 |
|------|----------|----------|
| 缺表 | `CREATE TABLE`（来自模板） | 是 |
| 缺列 | `ADD COLUMN` | 是 |
| 列定义不一致 | `MODIFY COLUMN` | 否（caution） |
| 多余列 | `DROP COLUMN` | 否（dangerous） |
| 缺索引 | `ADD INDEX` / `UNIQUE` | 是 |
| 索引不一致 | drop + add | 否（caution） |
| 多余索引 | `DROP INDEX` | 否（dangerous） |

每条变更绑定：目标实例、库、表、风险级别（`safe` / `caution` / `dangerous`）、SQL 文本。

## UI 页面

1. **连接管理** — CRUD、测连通、密码只写不回显  
2. **表组管理** — pattern、表列表、关联实例  
3. **同步工作台** — 主流程（选模板 → 扫描 → 勾选 → 执行）  
4. **执行历史** — 最近任务：时间、模板、成功/失败数、可展开 SQL 与错误  

扫描时部分实例失败：标红失败目标，不丢弃其它成功结果。

## 错误处理

- 连接失败 / 权限不足：标记该目标，继续其它目标  
- 执行失败：保存 MySQL 错误信息；按「继续 / 遇错即停」策略处理  
- 模板表不存在或表组未配置表：拒绝扫描并提示  

## 安全

- 仅本机监听  
- 密码密文 + 本地密钥；接口不回传明文  
- 必须勾选 + 二次确认后才执行；无静默全量同步  

## 验收标准

1. 可配置 2+ 实例，YAML 中密码为密文  
2. 能按 `order_*_*` / `product_*` 发现库，仅对比表组内指定表  
3. 人为制造缺列/缺索引后，扫描列出正确 SQL  
4. 勾选子集执行后，目标在所选变更上与模板一致  
5. 故意失败一条 SQL 时日志清楚，继续/停止行为符合选项
