## 背景与目标

多 MySQL 实例、多租户（及按年/分片）分库场景下，需要：

1. 像 Navicat 一样浏览：连接 → 库 → 表 → 字段/索引（含注释）
2. **模式 1**：指定现有库为基准，勾选表，将结构同步到规则命中的全部分库
3. **模式 2**：粘贴 DDL，在规则命中的多库上投放（仅允许结构类语句）

租户可能分布在不同服务器；库名由可组合规则生成，例如：

- `account_demo`（逻辑名 + 租户）
- `order_2025_demo`（逻辑名 + 年 + 租户）
- `order_1`（逻辑名 + 分片）
- `order_demo_2025_1`（逻辑名 + 租户 + 年 + 分片）
- `order`（仅逻辑名）

交付形态：**单机 macOS 应用**（Tauri 2），无独立客户端/服务端进程。

## 范围

### 首版包含

- Tauri 2 + Vue 3 单机 App
- 多连接实例管理（密码密文）
- 连接树浏览至表结构（表注释、字段注释、索引）
- 可组合命名规则（逻辑名 + 可排序部件：租户 / 年 / 分片）
- 模式 1：现有库作基准 → 勾表 → 扫描差异（展示注释）→ 勾选执行
- 模式 2：DDL 粘贴 → 白名单校验 → 预览目标库 → 执行
- 本机执行历史
- 打出可运行的 macOS `.app`（可选 `.dmg`）

### 首版不包含

- Windows / Linux 打包（可后续加）
- 自动更新
- 数据迁移 / 外键 / 分区同步
- 云端账号体系
- 浏览器版 / 独立 HTTP 服务端

## 架构

```text
macOS App (Tauri)
├── Vue UI：连接树、结构页、基准同步、DDL 投放、规则、历史
└── Rust 核心（Tauri commands）
    ├── 连接与 MySQL 访问
    ├── 规则展开 / 库匹配
    ├── Schema 抽取、Diff、SQL 生成
    ├── DDL 校验与多库执行
    ├── 扫描/执行会话缓存（前端只传 id）
    └── 配置与密钥（Application Support 目录）
```

无 `uvicorn`、无浏览器直连数据库。UI 仅通过 Tauri `invoke` 调用本机 Rust。

## 安全（最严档）

1. 单机进程，不对外监听 HTTP
2. 连接密码密文落盘；密钥在应用数据目录（权限收紧）；UI 不回显明文
3. 差异/待执行 SQL 缓存在 Rust 侧；前端执行只传 `scan_id` / `item_ids`（或等价 token），不接受客户端篡改 SQL
4. 所有执行须预览 + 二次确认
5. 模式 2 拒绝 `DROP` / `DELETE` / `UPDATE` / `TRUNCATE` 等危险语句（白名单结构 DDL）

## 连接模型

| 字段 | 说明 |
|------|------|
| id / name | 连接标识与显示名 |
| host / port / user / password | 连接信息（password 密文） |
| enabled / remark | 可选 |

左侧树根：连接 → `SHOW DATABASES` 下列库 → 下列表 → 右侧展示结构。

## 命名规则模型

| 字段 | 说明 |
|------|------|
| id / logical_name | 如 `order`、`account` |
| parts_order | 逻辑名固定首位；其后为有序列表，子集来自 `{tenant, year, shard}` |
| tenants | 租户字符串列表 |
| years | 年份列表或起止年展开 |
| shards | 分片列表或 `1..N` |
| connection_ids | 在哪些连接上查找物理库 |

物理库名：`logical_name` + 按 `parts_order` 用 `_` 拼接各部件取值的笛卡尔展开（仅名时无后缀）。

规则命中的库在树或列表上可显示逻辑名徽章。

## 模式 1：基准对齐

1. 选择基准：某连接 + 某已存在库  
2. 勾选要同步的表（列表展示表注释）  
3. 选择逻辑库规则 → 展开目标库（跨绑定连接；排除基准库自身）→ 可再剔库  
4. 扫描：Rust 抽取基准/目标表结构并 diff，结果缓存；UI 展示变更项，**含表注释、字段注释**  
5. 勾选执行项（危险默认不勾）→ 确认 → 按缓存 id 执行  
6. 按目标库串行；遇错可继续或停止；写入历史  

对比范围（首版）：列（含注释）、索引/主键、表注释；不做外键/分区。

## 模式 2：DDL 投放

1. 选规则（+ 可选剔库）  
2. 粘贴一条或多条 SQL（`;` 分隔）  
3. Rust 校验：仅允许结构白名单（如 `ALTER TABLE` 加/改列/加索引、`CREATE INDEX` 等）；拒绝 `DROP`/`DELETE`/`UPDATE`/`TRUNCATE` 等  
4. 预览命中的连接/库与 SQL  
5. 确认后按库串行执行并记录结果  

## UI 结构

- 左：连接树（刷新、测连通）  
- 右页签：结构 | 基准同步 | DDL 投放 | 规则 | 历史  
- 结构页：字段（注释列）、索引、建表摘要
